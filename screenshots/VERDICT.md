# UI-4 五面截图比对 · 人工复核结论（2026-10-08）

> 机器比对报告见 [compare-report.json](./compare-report.json)（pixelmatch 5 面全 FAIL：overview 12.1% / code 64.2% / agent 66.0% / cards 57.3% / assets 55.1%）。
> **结论：FAIL 全部为结构性偏差，非施工缺陷；⓪总览面构图/令牌/状态色纪律与 round-03 基准逐块对齐。** 本文件是施工方案 §11.4 要求的"偏差记录"。

## 一、为什么五面全 FAIL 但不阻塞

机器阈值 ≤5% 只在**同源、同尺寸、同数据态**时有意义。本次比对三个前提都不成立：

1. **基准是设计稿，不是实现基准** — `ui-design/round-03/shots/r5-*/r6-*/page.png` 是 a-deep.html 高保真原型的截图（数据全逼真：47 对象 / 12/12 ✓ / 8.4MB / 164 卡 / 98% 素材），不是任何前序实现窗口的验收基准。UI-2/3 完工时**未做过像素级比对**（其验收是"组件交付 + 工程验收全绿 + 浏览器冒烟不白屏"），故 ①②③④ 的 55-66% FAIL 是**历史欠账**，不属 UI-4 施工范围（UI-4 只新做 ⓪ + 顶层接线）。
2. **数据态不同** — 当前截图取自真实运行态：TTS 未连接（状态行 ● 红）、hub 0.7.1 降级（appMode=standalone，无 /v1/files）、冒烟包仅 2 个脚本（卡/素材全空态）、死链 0 / 待签 0。基准稿所有区块都有逼真数据。像素差异里一大块是"有数据 vs 空态"。
3. **尺寸裁切偏差** — 基准 1280x900（设计稿视口），当前 1280x720（IAB 默认视口），pixelmatch center-crop 后仍有 180px 高度差的内容错位。

## 三、动效三件套人工核验（对照 r7-motion/dialog/switch 探针帧）

- **工作面滑入**（r7-switch）：`routes.css:35-45` `.route-slide` transition transform var(--dur-move) var(--ease-out) + `.route-slide-pre{translateX(56px);opacity:0}`，与 a-deep.html:296-297 逐字一致；五面切换实测有感（截图间隔 900ms 内过渡已完成）。
- **首次进入阶梯**（r7-motion）：`Overview.css` 工序章 `:nth-child(1..5)` delay .02/.07/.12/.17/.22s + 内容块 .26/.32s，与 a-deep.html:302-307 逐字一致。
- **确认门生长**（r7-dialog）：`ConfirmGate.css:40-53` transform-origin bottom right + scale(.7)→1 + var(--dur-pop) var(--ease-pop)，UI-2 已交付，本次核验视觉参数与基准一致（实现用 @keyframes 而非 transition，Stage A 已记录为"视觉/时长/缓动/原点全部一致，只差取证机制"，不阻塞）。
- **prefers-reduced-motion**：tokens.css:86-93 全局 `transition:none!important` 兜底，三件套无需重复声明。
